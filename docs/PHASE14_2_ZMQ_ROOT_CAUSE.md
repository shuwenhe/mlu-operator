# Phase 14.2 — ZeroMQ shutdown investigation

The exact Phase 14.1 invocation ran with the same image digest, two cards, same-process EngineCore, and the four frozen fault definitions. Each failed request was cancelled. Both workers exited by 20:09:08 CST. At 20:09:48 the parent watchdog captured `Context.__del__ → Context.destroy → Context.term` underneath Vendor's explicit `gc.collect()`. The parent and Python resource tracker were still alive. No Worker_TP process remained. The parent's kernel thread state showed its main polling thread and ZeroMQ reaper/I/O threads. CNMON had no running MLU processes.

The installed Vendor `MessageQueue.shutdown()` only cancels reads. Its context tracks sockets via weak references and its owners do not close the sockets explicitly. In an isolated reproduction with this same PyZMQ build, a context and its socket were placed in one unreachable cycle. When GC called the context destructor, its weak set still reported a length of one but yielded no live socket. The ensuing `term()` blocked. Explicit owner-side socket close followed by context termination completed on the same fixture.

The Vendor RPC future retains a response-queue closure. Its failure path stores an exception with a traceback. That path can keep references to queues until cyclic collection. The live ownership trace in `zmq_shutdown.log` identifies the exact queue involved.

The instrumented hardware retry identifies the blocked context as the parent-side rank 0 response queue. Its data, notification and two cancellation sockets were open on executor shutdown entry. The executor returned with its worker monitor gone. The broadcast context and rank 1 response context terminated successfully. Rank 0 context destruction reported four tracked sockets but zero live weak references, and its synchronous termination did not return. The isolated cycle reproduces that specific pattern. The fix must retain the queue's sockets until the owning thread can close them after Vendor worker shutdown and before EngineCore's garbage collection.
