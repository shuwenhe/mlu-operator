# Phase 13.3.3 — O projection root cause

Frozen `phase8_candidate_bf16` traverses K in increasing 128-channel tiles. Within each tile term p updates FP32 lane p%64, with a separately rounded product and add. Only after all K tiles does it execute its fixed 64-lane fold. The packed 128-column tile maps back via matrix_rhs_slot. Phase 13.2 Row runs precisely that kernel on each contiguous rank-local K shard, folds locally, then sums the folded FP32 outputs through the Vendor CNCL device group. The rejected operation is therefore regrouped both in the lane recurrence and in the final fold. Deterministic CNCL SUM alone cannot restore information lost before communication.

The original recorded TP=8 failure uses prompt 7, decode step 2, index 1134. Distributed FP32 0.0543212890625 is the midpoint, while unsharded FP32 0.0543212965130806 is two FP32 ULPs above it. BF16 RNE returns 0.05419921875 and 0.054443359375, respectively. The BF16 cast and residual remain after the FP32 result.

Candidate implementation passes the *unfolded running state* in global rank/K order. Each rank computes with its actual local packed weight. The last rank folds once with the original tree, then broadcasts the FP32 result. The key distinction is continuation from the previous state, since SUM of independently initialized lane vectors also loses the sequential rounding. This exception changes the collective pattern only for the isolated compatibility experiment; the existing normal Row path remains available and frozen.

| Strategy | Numerical expectation | Traffic, scratch and complexity |
|---|---|---|
| A. Ordered continuation | Preserves each rounded addition and fold. Hardware validation required. | TP−1 state broadcasts plus one result broadcast. FP32 64 lanes × M × 2048 scratch per rank. Serial K stages. |
| B. Independently accumulate then defer fold | Preserves fold only. The cancellation counterexample rejects lane SUM as an exact strategy. | One lane-vector reduction, same scratch as A. No exact hardware candidate selected. |
| C. Change deterministic reduction tree or K placement | A tree over folded scalars cannot recover the pre-fold state. Contiguous tile order and recurrence are the acceptance constraint. | One output-sized reduction for the historical path, measured in Phase 13.3.2. Unimplemented trees have no latency claim. |
| D. Redesign accumulation/layout | A fixed associative high-precision accumulator changes the frozen recurrence; it can change which side of a midpoint is selected. A column-distributed full-K O would additionally change audited weight ownership and require gathered V. | Alternative layout merits separate engineering work; no measured latency or scratch result for an unimplemented candidate. |

A viable alternative C/D candidate is to shard O by output columns, gather the full BF16 activation before GEMM and gather the resulting FP32 output before casting. Every rank would use full K for its owned output tiles, which are also 128-aligned. For M inputs the two assembled payloads are 4,096×M and 8,192×M bytes. This would change the audited O shard ownership. It passed full numerical and stability checks at TP=1/2/4/8 in the isolated output-axis experiment. The selected A path preserves rank-local O weight ownership. Strategy B's reset-state failure is demonstrated by the host cancellation test and by its native TP=2 run. Its TP=1 control passed. Each TP=2 rank had three O and three residual tolerance violations. TP=4/8 were NOT RUN after the TP=2 failure.
